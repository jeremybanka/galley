# galley.md

Compile trusted MDX documents and executable components to checked-in Markdown.

- Galley owns Markdown formatting defaults across the CLI, API, and previews using pinned dprint dependencies. No additional installation or configuration is needed. Code blocks, raw HTML, and YAML frontmatter retain their contents; project formatting settings are not read.
- Use `galley write [input] [output]` to generate Markdown and `galley check [input] [output]` to detect drift. Failed checks print existing/generated line numbers, visible whitespace (`·` spaces, `→` tabs, `␍` carriage returns), and contextual changes to stderr without writing output. Terminals and GitHub Actions use colored lines and character highlights; `NO_COLOR=1` or `FORCE_COLOR=0` disables color. The default input is `README.mdx`. Output precedence is explicit CLI/API output, YAML frontmatter `galley.output`, then the input extension replaced with `.md`.
- Frontmatter output paths are relative to the source directory; a leading `/` resolves from the nearest ancestor with a `.git` directory or file. Explicit CLI/API paths keep working-directory and filesystem-absolute semantics. Only `write` creates missing destination directories. Galley settings are omitted from generated Markdown; other frontmatter is preserved. Imported documents never choose additional destinations.
- Import source examples with `with { type: "code", lang: "ts" }`. The language defaults to the file extension. Code imports read the file without executing it.
- Components return Markdown nodes, text, elements, or promises of those values. Use `Markdown` to parse generated Markdown and `Code` to create fenced source examples.
- Native JSX tags emit HTML with typed HTML/SVG attributes. Markdown syntax stays Markdown. Use `Markdown.Table` with `tr`, `th`, and `td` children to generate GFM pipe tables; start with one header row and matching cell counts, with optional left/center/right alignment on `th`. Cells support inline Markdown and HTML. Merged cells, structural styling, captions, footers, and block content are conversion errors. Ordinary `<table>` remains HTML.
- Use `Comment` to preserve an HTML comment in generated Markdown. Its children render as Markdown with surrounding whitespace trimmed and cannot contain HTML comment delimiters. MDX comments (`{/* ... */}`) remain source-only.
- Use native JSX for HTML markup and custom elements. Use a CSS string for style; event handlers and refs are unsupported. `Html` remains a wrapper-free conversion of Markdown nodes to HTML, and `Html.Element` is deprecated but supported. Built-in Galley components reject unknown props; declare explicit `Component<Props>` types for custom components.
- Galley extends MDX with TypeScript in import/export blocks, brace expressions, props, and spreads. Use exported declarations; bare top-level declarations are prose. JSX inside expressions is TSX; direct MDX children remain Markdown. Compilation erases types, while the TypeScript 7.1 mapper checks original TSX. Standard MDX tools may reject this dialect.
- Format authored MDX with `dprint-plugin-mdx`, which bundles its own TypeScript formatter. Generated Markdown formatting remains built into Galley.
- Use the component's second argument, `DocumentContext`, for paths relative to its containing document. Imported MDX documents get their own directory context.
- Pass esbuild plugins through `compileMarkdown(input, { plugins })` or `runGalley`. Custom plugins run before built-in handlers and can consume arbitrary import attributes using esbuild's native module identity.
- Ordinary document imports and components execute during compilation. Only compile documents and plugins you trust.
- Install the npm-shipped VS Code extension with `galley vsix [editor]`, or build it with `galley vsix build [outputDirectory]`. Select the **galley.md** language for `.mdx` documents. The VSIX includes the pinned TypeScript 7.1 runtime for the current platform.
- Register `{ "package": "galley.md", "extensions": [".mdx"] }` in `tsconfig.json`'s `contentMappers` array for configured projects. CLI type checking requires TypeScript 7.1 and `--runExternalCode`.
- Component output appears as ghost summaries, full Markdown hovers, and native inline peek views. Preview refresh evaluates on open/save or explicit refresh, keeps edited regions and open peeks available with a stale label while tracking their source ranges, and only runs in trusted workspaces. Syntax and component errors appear in Problems while healthy regions remain available; compilation stays strict. Separate preview processes have a timeout and are not security sandboxes.
- Describe plugin import types with the mapper's `options.importTypes`. Build hooks remain esbuild plugins; editor metadata never executes those hooks.
